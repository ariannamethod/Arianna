# Arianna — Body Log

Landed engineering facts for Arianna's inference body. One line per change: what changed → result → proof (command / benchmark). Neutral and reproducible; the working kitchen stays local. This log covers the body only — companion resident models are logged separately.

---

## Substrate

**Qwen3-30B-A3B-Base** — 30.5B total, 3.3B active, 128 experts (top-8), `qwen3moe`, Apache 2.0. A rented pretrain base; identity is grown on top (Janus Constitution, Article 6.5). Chosen for an irrevocable open licence, a clean pretrain base (no post-training alignment layer), and MoE physics whose expert pool fits the host's page cache.

## Runtime

Colibri out-of-core MoE engine (pure C) + notorch kernels; expert pool memory-mapped, resident footprint small by design. Host: a dedicated Linux node, 6-core AVX2, 31 GB RAM. llama.cpp serves only as oracle/baseline, never as the runtime.

## Phases

- **T0 — baseline breath ✅** (2026-07-24). `llama-bench`, `qwen3moe 30B.A3B Q4_K_M`, 17.28 GiB, CPU 6 threads: prefill 38.47 t/s, decode 11.99 ± 0.23 t/s. Coherent multilingual generation. — llama.cpp build 9638.
- **T1 — BF16 to disk ✅** (2026-07-26). Full BF16 checkpoint staged (57 GB, 16 safetensors) for the converter.
- **T2 — arch parity ✅** (2026-07-26). Tiny-random Qwen3MoE (torch oracle, raw-greedy) + a pure-C forward (`qwen3moe_p0.c`): loader → RMSNorm → GQA attention (q/k-norm, rotate_half RoPE) → softmax router (top-K, norm) → per-expert SwiGLU. **Token-exact: teacher-forcing 30/30, greedy 20/20; cc 0 own warnings.** No YaRN / MLA / shared-expert (the architecture uses none). Arch reproduces the torch reference exactly; full-weight parity confirmed later at T4 post-conversion.
- **T3 — converter ✅** (2026-07-26). `convert_qwen3.py`: BF16 → Colibri container. Per-expert SwiGLU weights row-symmetric int4 (packed two nibbles/byte, one F32 scale per output row, byte-exact to the engine's decode); the router, norms, attention, embeddings and head stay full precision (resident quantization is a later phase). **Experts 57.98 GB → 14.58 GB (25.2%); container 16 shards, 17.7 GB, 37299 tensors.** Format verified by round-trip against the source weights: reconstruction error lands on the int4 quantization floor (relative-L1 ≈ 0.16, cosine ≈ 0.988) across sampled layers 0–44 — a packing/indexing error would be O(1), so the layout is byte-correct. The engine's planner reads the container: 14.6 GB warm experts resident in 27.7 GB RAM, cold-expert I/O 0 GB.
- **T4 — first Colibri breath ✅** (2026-07-27). `qwen3moe.c` front-end (graft: T2 forward math + olmoe.c streaming scaffold + glm.c fused int4 dot). Wiring token-exact vs T2 on tiny (tf 30/30, greedy 20/20, `-DACC_DOUBLE`); int4 kernel token-exact vs the f32 oracle on tiny. Full 48-layer forward on the 30B container: **3.38 t/s warm** (256 tok, hit 96%). Diagnosis: memory-bound — 5.83 GB/token × ~19.7 GB/s measured stream.
- **T5 — resident quantization ✅** (2026-07-27). Attention q/k/v/o → int4, lm_head → int8; router/norms/embeddings stay full precision. Container 15.35 GB, dense resident 3.1 → 1.4 GB. **5.78 t/s warm**; the bottleneck moved from memory to compute (naive nibble unpack).
- **T5b — int8-activation dot (idot) ✅** (2026-07-27). Per-vector int8 activation quant + AVX2 maddubs kernels (glm.c port) for the int8 head and int4 experts; attention stays exact. **7.13 t/s warm @256** (6.07 @128), effective stream 12.3 GB/s. Expert-idot pays off at batch=1 on AVX2 — measured, not assumed.
- **T5c — Q6_K head ✅ / tempo gate not taken** (2026-07-28). lm_head requantized BF16 → Q6_K (210 B / 256 values, ggml block layout) by the project's own converter; layout byte-exact to the reference decoder (max|diff| = 0 on both oracle and own bytes, N=4096 rows), round-trip relL1 0.0202 vs oracle's 0.0183 (absmax vs rmse-optimal scale search — systematic, not positional). Head 311 → 255 MB (policy 1.665 GB/token); first x86 AVX2/FMA path for the vendored `nt_q6_k_rows` kernel (+35%, 4.65 → 6.30 t/s). Clean re-measure of node bandwidth: **35.36 GB/s** (prior 19.7 figure was a derived, stale estimate) → physical ceiling 21.2 t/s. Tempo landed at **6.3 t/s vs the ≥11.0 gate**: the head costs only 16 ms of the 159 ms token budget; the gap lives in the int4 expert/attention kernels (140 ms). Counterintuitive, recorded: the Q6 head is slower than the int8 head (6.30 vs 7.09) because Q6_K has no int8-activation path — better bytes and accuracy, worse compute. Fresh oracle column, same box: llama.cpp Q4_K_M tg256 12.88 ± 0.06.
- **T5d — expert/attention kernels ✅** (2026-07-28). Six moves, each measured before and after, token-integrity probes on every one (baseline flips reproduced to the fifth digit of their margins). (1) expert reads were hitting disk every LRU miss — an inherited `POSIX_FADV_DONTNEED` dropped pages in the hot loop (0.57 GB/s); page cache restored. (2) warm-measurement canon aligned with llama-bench: LRU warmed over 400 tokens, then KV reset, clean 256-token window. (3) attention moved to the int8-activation integer dot — the inherited "+12% ppl" claim did not reproduce on this model (tiny 24/30 vs 23/30 baseline; first 16 generated ids on 30B identical to exact). (4) fused top-k expert pass and fused q/k/v: 1152 OMP regions per token → 2 per layer; triple re-quantization of the same row eliminated. (5) QK scores: scalar double chain → AVX2/FMA with double lanes — zero flip movement. (6) Q6_K head on the int8-activation dot (upstream notorch branch `q6-i8-dot`: kernel + thread fan-out for a matvec that had never threaded); silu+expf parallelized. **6.3 → 11.79 t/s warm (median of 5, hit 100%, RSS 9.87 GB, 6 threads); gate ≥11.0 taken by all runs. Oracle same session: 12.85–13.05 (median 13.00) — 91% of llama.cpp on the same box; trophy not taken.** Residual efficiency map: experts 76% of node bandwidth, attention 68%, head 31% — the head anomaly (255 MB in 23.2 ms) is the identified next reserve (~+2.2 t/s: per-call thread spawn and per-call activation re-quant in `nt_qmatvec_i8`). Prefill 11.6 vs oracle 43.2 — unfused S>1 path, out of mandate, open.
- **T5e — head efficiency ✅ / ORACLE OVERTAKEN** (2026-07-28). Direct phase measurement refuted all three planned hypotheses (thread spawn 1.1%, activation quant below timer resolution, row split 85%-efficient) and exposed the real thief: the engine's OpenMP team spin-waits by default, and the vendored matvec spawned fresh pthreads to fight it for the same six cores — 12.51 ms in isolation vs 23.19 ms in situ. Fix upstream (notorch): under `_OPENMP` the packed matvecs join the caller's team; checksum bit-identical across four split policies. Head 23.19 → 12.67 ms (31% → 57% of node bandwidth); int8-activation attention and head became defaults (exact paths kept under env). **Final, both columns own-hand on an idle box, same input: body tg256 median 13.99 (13.81–14.11), llama.cpp Q4_K_M tg256 11.90 ± 1.09 (builder pass: 13.98 vs 12.68) — the engine overtakes its oracle by ~10% at 71.1 ms/token. ×2.25 from T5c in one day.** Residuals: experts 76% of bandwidth (memory-floor bound), prefill 11.8 vs oracle 41 (unfused S>1 path — next mandate after the tokenizer).
- **T5f/T5g — quality parity, two gaits ✅** (2026-07-29). A ppl-methodology error self-caught and retracted: our window scored all 511 tokens where llama-perplexity scores the last half (`first = n_ctx/2`) — the earlier "1.59× worse" claim was a metric artifact; true t5c gap was 1.35×. The converter then closed it: rmse row scales (free, −0.34), Q4_K experts with weighted scale/min search (make_qkx2 class), attention to Q4_K, and the oracle's own recipe read from its GGUF as data — Q4_K_M is a mix, Q6_K on 24 layers of ffn_down_exps and attn_v; replicated on the same indices. Kernels: Q4_K int8-activation dot (32/32 grid, no sign trick), caller-parallel rows API for fused MoE passes, lane-scheme hadd trees for Q4_K and Q6_K. One optimization withdrawn by its own measurement: a "bit-identical" vectorised tail differed by one compiler FMA contraction — float64 perplexity over 2040 log-probs caught the ulp that argmax and six-digit relL1 cannot; a bit-level kernel A/B (objcopy --redefine-sym old/new side by side) is now the standing instrument for kernel-class changes. **Final, one session, both columns own-hand gated: parity container tg256 11.24 t/s at PPL EN 4.8712 / RU 2.8384 vs oracle 4.8569 / 2.8300 (+0.3%, inside the bar); light container tg256 14.30 at PPL 6.54; oracle 13.15 ± 0.21. One body, two honest gaits.** Prefill stays the open gap: 11.94 vs 41.96 — decode-shaped matvec per token vs batched GEMM; architecture item, next mandate.
